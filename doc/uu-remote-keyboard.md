# UU 远程键盘：原因、使用与验收

## 已确认的兼容性限制

静态检查对象来自 [网易 UU 官网](https://uuyc.163.com/)：官网的 `https://adl.netease.com/d/g/uuremote/c/gw?type=android` 指向 `https://api.nrd.nie.163.com/api/v1/release/dl/2?channel=gwqd`。检查包为 `com.netease.uuremote`，版本 `4.40.0`（440000），SHA-256：

```text
2cc14a4a3fb18066ac0f38ccbc08b17bc05e6d72fb150517269e74316554fef9
```

三项证据解释了“仅退格和回车有效”：

1. `InvisibleEditText` 的 `InputConnectionWrapper`（该版本混淆名 `Kb.a`）只把 Enter、Delete 的抬起事件转发远端；普通字母留在本地编辑框。
2. 同一组件的 `setComposingText` 仅缓存文本，`finishComposingText` 和 `commitText` 最终走文字提交，不能据此触发远端拼音。
3. `ScreenActivity` 在“输入法”模式隐藏 `GVDeviceInputView`，退出后恢复焦点。硬件处理器（`p238r5.e`）接收键盘来源且设备具备字母输入能力的事件；该路径不依赖字母扫描码，也没有统一排斥虚拟设备。

因此补全 `scanCode` 不是 UU 问题的根因修复。2026-10-04 在 Android 17 / UU 4.42.0 的 ADB 原型中，UHID 字母键盘已登记为外接字母键盘：焦点在 `InvisibleEditText` 时无远端反应，切换到 `GVDeviceInputView` 后，同一设备发送 `nihao` 成功触发远端拼音（用户确认）。这不是应用完整链路或所有组合键的验收。

应用改用 Shizuku 启动 `/system/bin/hid -`，通过 `/dev/uhid` 注册键盘并发送 HID 报告；不再把 `injectInputEvent` 当成外设。无需蓝牙连接远端 Mac。目前保留 Android 14+ 的支持范围，并要求系统存在 HID 工具与 UHID 权限，不代表所有 ROM 均兼容。设备注册必须等待 Android 输入框架识别，不能仅凭子进程启动成功。依据：[AOSP HID 工具](https://android.googlesource.com/platform/frameworks/base/+/master/cmds/hid/README.md)。

**安全边界**：HID 跟随系统焦点，不具有原 UID 定向注入的原子保护。每次按下前重新检查 UU 前台窗口、`GVDeviceInputView` 及文本连接状态；未知格式、其他应用、通知栏、文本输入模式或非主显示屏均拒绝。检查与按键分发之间仍有竞争窗口，输入时不要切换应用。不会自动降级到未检查的输入方式。

## 使用步骤

1. 安装 [Shizuku](https://shizuku.rikka.app/zh-hans/guide/setup/)。在开发者选项开启无线调试，按 Shizuku 的配对引导输入配对码，再启动服务。
2. 打开 pcKeyboard 设置，授予 Shizuku 权限及“显示在其他应用上层”权限，启动远程悬浮键盘。重启手机后通常需要重新启动 Shizuku。
3. 返回 UU 并连接 Mac，明确切换底部“电脑键盘”，关闭“输入法”面板，再点远端编辑框。仅收起手机键盘不一定退出 UU 文本输入模式。保留 pcKeyboard 悬浮键盘。
4. 在远端 Mac 切换中文拼音输入法，连续输入 `nihao`，检查是否出现远端拼音候选；测试空格选词、数字选词、退格、回车及 `⌘C`。
5. 结束后关闭悬浮键盘，释放按键并销毁 HID 设备。拒绝授权或 Shizuku 停止时，应显示不可用状态；不要在按键发送过程中切换应用。

Mac 组合键还需要配置 UU 的右 Ctrl 替代映射，参见 [Mac 组合键说明](mac-keyboard-shortcuts.md)。

设置页将 UU 悬浮键盘入口、权限与兼容选项放在首个独立分组；按键布局及外观由两种键盘共用。“普通输入法”的输入方式、语言和纠错设置不控制 UU 浮窗的传输通道，也不切换 Mac 的输入源。更新只检查本仓库 `ababdotai/FoldableKeyboard`，不会下载原项目安装包覆盖此版本；未发布 Release 时可能提示检查失败。

## 浮窗入口与屏幕避让

系统输入法列表中的 pcKeyboard 与 UU HID 浮窗是不同入口。普通输入法仍通过 UU 的文本输入组件，不能替代已验证的 HID 通道。请从设置启动浮窗；收起后点击小型“键盘”按钮恢复，也可从常驻通知恢复，不需要返回输入法列表。

展开时拖动“拖动”柄调整位置；收起按钮可二维拖动，点击恢复。收起会隐藏诊断、取消待发输入并重置修饰键，不退出会话；“关闭”或通知中的“停止”才结束会话并销毁设备。浮窗不再保留普通输入法使用的 90dp 透明弹窗预留区。

**自动避让尚不支持**：该窗口是 `TYPE_APPLICATION_OVERLAY`，不是系统 IME 占位窗口，不能让 UU 自动获得输入法高度或触发其画面平移。将 UU 切回“输入法”以获得避让又会改变输入通道；不能当作等价解决方案。目前需移动/收起浮窗，或使用 UU 自身已有的画面调整功能。不要通过全局修改手机分辨率或显示缩放来模拟避让。

可人工验证的替代方式：保留 UU 自带“电脑键盘”面板，并将 HID 浮窗移到同一区域。已检查的 UU 4.40 代码对 fullkey 模式也会按键盘顶部与最近点击位置执行条件式画面平移（`ScreenKeyboardFragment.C/n/B` 及 `Y8.C1325w0/C1331y0`）；但手机 4.42 的实际效果、两套面板高度匹配尚未确认，不保证自动避让。应用不会自动点击或修改 UU 的界面。

## 分层诊断与报告

设置 → **UU 键盘分层诊断** 可查看前置条件；使用浮动键盘时，点击顶部 **诊断** 可在不抢走 UU 焦点的面板中观察实时计数。面板只诊断 Shizuku 浮动通道，不统计普通输入法 RAW 通道。

1. **环境与权限**：Android API 34+、UU 安装版本、悬浮窗权限、Shizuku 13+ 运行与授权状态。
2. **服务连接**：未启动、连接中、已连接、断开或超时。Binder 已连接不等于可以投递。
3. **HID 设备检查**：可能启动子进程、注册键盘并等待 Android 识别，但不会发送测试按键；并非纯只读操作。
4. **HID 提交**：实际尝试、报告完整提交、未完整/失败、丢弃及取消的逻辑按键数量；区分队列溢出与超时。部分提交不会记为完整，失效会话的延迟结果不会覆盖新会话。
5. **远端接收**：始终标记“未确认”。写入 HID 子进程不证明 Android 分发、UU 转发或 Mac 收到；本应用不能自动读取 UU 的按键替代设置。

打开浮窗面板会重新执行 HID 设备检查；设置页只查看状态，不会申请权限或启动服务。输入无反应时先看第 4 层：全零可能是仍在使用普通 IME；焦点拒绝则切换 UU 电脑键盘；报告完整提交仍无反应则检查远端焦点和 Mac 输入源。

**清零统计** 只清除诊断计数，不重连或发送按键。计数仅保留当前进程最近一次浮窗会话，重启进程或开启新会话后重新统计。**导出脱敏报告** 只在点击后生成私有缓存文本，通过系统分享面板临时授予接收应用读取权限；不自动上传。报告仅包含版本、权限、固定状态码及聚合计数，不包含输入文字、按键码、修饰键、逐键时间、剪贴板、账号或设备标识。浮窗导出时会收起键盘和诊断面板，为分享界面腾出空间；分享会切走 UU 焦点，返回后需重新点击远端输入框，再展开键盘。

## 验收边界

2026-10-04，用户确认安装修复版后，悬浮键盘输入功能正常。此前“尝试增加、完整提交始终为 0”的直接原因是焦点窗口正则中的闭括号未显式转义：桌面 JVM 接受该表达式，Android 正则引擎却抛出 `PatternSyntaxException`，安全检查因此拒绝全部按键。修复保持原有焦点限制，并使用真实 APK 在 Android 上验证当前焦点及 5 项接受/拒绝用例；只通过 JVM 测试不足以覆盖此差异。只读设备验证工具位于 `test/device/HidFocusProbe.java`，不发送按键。

编译和自动化测试验证事件、权限与状态处理，不能证明特定手机及 UU/Mac 会话已经成功。真机验收还需覆盖折叠、旋转、切换应用、连接重建和权限失效。UU 后续版本可能改变输入实现。公开安装包及静态分析输出只留在临时目录，不随代码提交。

使用 JDK 17 运行回归测试、Lint 及 Debug/Release 构建：

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleRelease
```

可安装的签名包位于 `app/build/outputs/apk/debug/app-debug.apk`。未配置发布密钥时，Release 包未签名，不能直接安装。连接启动超过 10 秒会停止等待并提示关闭浮窗后重开，不会补发超时期间按下的字母。
