# FoldableKeyboard icon

The launcher artwork is based on the keyboard photograph supplied by the project owner. It retains the silver-and-white keyboard and adds an **FK** monogram. The built-in image generation tool produced the composition; no external image-generation API key was used.

- README/master artwork: [`public/icons/icon.png`](../public/icons/icon.png).
- Android raster: [`foldable_keyboard_icon.png`](../app/src/main/res/drawable-nodpi/foldable_keyboard_icon.png), resized to 432 × 432 for packaging.
- Adaptive foreground: [`ic_launcher_foreground.xml`](../app/src/main/res/drawable/ic_launcher_foreground.xml), with 20% insets to keep the keyboard and monogram inside launcher masks. Android supplies the outer shape; the artwork is not pre-rounded.
- Native Android rendering previews are generated by `LauncherIconTest` under ignored `temp/branding/`.

## Generation prompt

Use case: compositing. Asset type: Android adaptive launcher icon for FoldableKeyboard. Image 1 is the edit target, a silver and white keyboard product photograph. Preserve the keyboard's recognizable original top-down shape, white keycaps, silver frame, and Mac modifier and inverted-T arrow layout. Make a polished square 1024x1024 icon composition on a clean solid white full-bleed background, without any pre-rounded outer border. Reposition and scale the complete keyboard photograph intact so it occupies approximately x=22% to78%, y=46% to69% of the square. Above it, add ONLY a bold crisp dark-graphite sans-serif monogram 'FK', centered around x=50%, y=35%, roughly 20% canvas width, with ample spacing. FK must read clearly at small app-icon sizes. Keep all meaningful foreground details within the central circular safe area of diameter66% so an Android launcher circular crop will not cut the keyboard or letters. Minimal premium silver-white aesthetic, subtle original photographic shading, no blue gradients, no extra objects, no Apple logo, no watermark, no other branding or captions. Output one finished app icon, not a mockup, not multiple variants.

The generated composition used a wider keyboard than requested, so the Android drawable supplies additional safe-area insets. This does not change the keyboard image itself. Adaptive sizing follows the [Android icon guidelines](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive).
